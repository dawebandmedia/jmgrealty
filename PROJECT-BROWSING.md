# Model names first, project names underneath

Listing cards show the model or unit name first as a bold heading, followed immediately by the linked project name in slightly smaller, readable text. Property type, location, price information and specifications follow. For example: Kayla Prime, then Amaresa Homes, then the remaining details. The model heading opens the model; the project name opens its project profile.

Desktop cards use 24 px model headings and 18 px project names. Mobile grid cards use 22 px and 17 px, while narrow mobile list rows use 20 px and 16 px. Titles wrap naturally. Featured properties, their selectors and model detail pages also show the model name before the project name.

The property catalog and homepage search open model results by default again. The compact grid/list controls, filters, dated price information, exact pricing notice, saved models and comparison flow remain available. Project browsing is an optional view, and the Project selector remains visible outside the collapsible mobile filter panel.

Project-only cards continue to lead with the project name and include category, location, description, imagery and model/unit-type counts. Those counts describe catalog records rather than available inventory. Filtered project cards indicate matching model counts, and their model links preserve the filters. Shared URLs retain explicit browsing modes. Ordinary and legacy model links open model results; explicit project-mode links still open projects.

The existing responsive layouts, ordinary buttons/selects, pressed states and reduced-motion behavior are retained. No animation package or media downloads were added. All 20 developments and 74 model/unit records are included with their original media and content safeguards.

Validation includes TypeScript, production build, focused source/link and URL-state checks, plus archive integrity and private-file exclusion checks. No automated test suite was run and no inquiry was saved. Live browser and physical-device visual checks remain unverified because the browser/approval restrictions from the earlier preview attempt have not been cleared.

Delivery is an updated local website ZIP only; no hosted site was deployed.
